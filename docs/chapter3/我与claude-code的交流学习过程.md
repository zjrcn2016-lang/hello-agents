## Q1: generated_ids 这段代码做了什么工作？

```python
generated_ids = model.generate(model_inputs.input_ids, max_new_tokens=512)
generated_ids = [
    output_ids[len(input_ids):] for input_ids, output_ids in zip(model_inputs.input_ids, generated_ids)
]
```

**A:** 分两步：

1. `model.generate()` 返回的是**输入 + 输出**拼在一起的完整 Token 序列，例如：
   - 输入：`[101, 234, 567]`
   - 返回：`[101, 234, 567, 890, 112, 333]`

2. 列表推导式把输入部分切掉，只保留模型新生成的 Token：
   - `output_ids[len(input_ids):]` → `[890, 112, 333]`

这样后续 `tokenizer.batch_decode()` 解码时，只得到模型的回答，而不是"问题 + 回答"混在一起。

## Q2: top_p 和 top_k 具体是什么？

**A:** 两个参数都是控制模型生成文本时从哪些词里随机选的策略。

模型每次生成一个 Token 时，会给词表里所有词打分，转成概率分布，然后从中随机抽一个词。

**top_k = 50**
只保留概率最高的 50 个词，其余全部丢掉，再从这 50 个里随机抽。作用：防止模型选到概率极低的奇怪词。

**top_p = 0.9**
不按数量限制，按累积概率限制。把词从高到低排列，累加到 90% 就停，只从这些词里抽：
```
"火箭"  40%  → 累计 40%
"卫星"  25%  → 累计 65%
"飞船"  20%  → 累计 85%
"苹果"   5%  → 累计 90%  ← 到这里停
```
作用：自适应调整候选数量——概率分布集中时候选少，分散时候选多。

两者同时用时，先用 top_k 砍掉尾部低概率词，再用 top_p 进一步缩小范围。

**temperature** 控制概率分布的尖锐程度：低温输出更确定，高温输出更随机。

## Q3: 自注意力机制（Self-Attention）的核心思想是什么？

**A:** 核心思想是：让序列中每个位置的词，都去"看"其他所有位置的词，然后决定自己该关注谁。

**直觉例子：**
- `"银行在河边"` vs `"银行在市中心"` — "银行"的意思不同，Self-Attention 让它看整句话后调整自己的表示。

**具体做法：** 每个词生成三个向量：

| 向量 | 作用 | 类比 |
|------|------|------|
| Q（Query） | 我想找什么信息 | 搜索关键词 |
| K（Key） | 我能提供什么信息 | 文档标签 |
| V（Value） | 我实际的内容 | 文档正文 |

计算过程：
```
注意力分数 = Q · K^T / √d_k
注意力权重 = softmax(分数)
输出       = 权重 × V
```

**与 RNN 的本质区别：** RNN 顺序处理，距离越远影响越弱；Self-Attention 并行处理，直接计算任意两词的相关度。

## Q4: 为什么 Transformer 能并行处理序列，而 RNN 必须串行？位置编码起什么作用？

**A:**

**RNN 串行的原因：** 每步隐状态依赖上一步，形成链式依赖无法跳过：
```
h2 = f(x2, h1)  ← 必须等 h1 算完
h3 = f(x3, h2)  ← 必须等 h2 算完
```

**Transformer 并行的原因：** Self-Attention 只需要所有词的 Q/K/V，这些在输入时全部已知，所有词可以同时计算：
```
词1的输出 = f(Q1, K_all, V_all)  ┐
词2的输出 = f(Q2, K_all, V_all)  ├ 同时计算
词3的输出 = f(Q3, K_all, V_all)  ┘
```

**位置编码的作用：** 并行化导致顺序信息丢失——`"猫吃鱼"` 和 `"鱼吃猫"` 词集合相同，Self-Attention 结果也相同。位置编码用 sin/cos 函数在词向量上叠加位置信号，弥补这一缺失：
```
输入 = 词向量 + 位置编码
```

## Q5: Decoder-Only 架构与 Encoder-Decoder 架构有什么区别？为什么主流 LLM 都用 Decoder-Only？

**A:**

**Encoder-Decoder（如 T5）：**
```
输入序列 → Encoder（双向）→ 上下文向量
                                  ↓
输出序列 → Decoder（单向）→ 交叉注意力 → 生成下一个词
```
适合输入输出格式差异大的任务，如翻译、摘要。

**Decoder-Only（如 GPT、Qwen、LLaMA）：**
```
[输入 + 已生成的输出] → Decoder → 生成下一个词
```
把输入和输出拼在一起，统一用带因果掩码的自注意力处理。

**主流 LLM 选择 Decoder-Only 的原因：**

| 原因 | 说明 |
|------|------|
| 统一建模 | 所有任务都变成"续写"，无需区分编解码阶段 |
| 扩展性更好 | 参数量增大时 scaling 效果更稳定 |
| 训练更简单 | 一个模型、一个损失函数，用下一个词预测训练 |
| 推理灵活 | 问答、翻译、代码、摘要全部用同一套框架 |
| KV Cache 友好 | 自回归生成时可缓存历史 K/V，推理效率高 |

## Q6: Decoder-Only 模型是所有任务都是续写，输出时自己截断吗？

**A:** 对，但不是截断，而是自回归生成。

**训练阶段：** 输入是完整对话拼接，模型预测下一个 Token，损失只算 assistant 回答部分：
```
<|system|>你是助手<|user|>今天天气怎么样<|assistant|>今天天气晴朗
```

**推理阶段：** 一个词一个词地生成，每次把已生成的词拼回输入：
```
第1步: [输入] → 预测"今"
第2步: [输入 + 今] → 预测"天"
第N步: 预测到 <|end|> 特殊符号 → 停止
```

**因果掩码的作用：** 保证生成第 N 个词时看不到后面的内容，使训练和推理行为一致。

**"截断"发生在哪里：** 不是输出截断，而是解码时只取最后一个位置的预测结果，前面输入部分的预测直接丢掉不用。

## Q7: Bigram 是什么？

**A:** Bigram 就是 N-gram 里 N=2 的情况，即相邻两个词组成的词对。

| 名称 | N | 含义 |
|------|---|------|
| Unigram | 1 | 单个词 |
| Bigram | 2 | 相邻两个词 |
| Trigram | 3 | 相邻三个词 |

Bigram 的核心假设：一个词出现的概率只取决于它前面那一个词。

## Q8: 用迷你语料库计算 "agent works" 在 Bigram 模型下的概率

语料库：`"datawhale agent learns datawhale agent works"`

**P("agent works") = P(agent) × P(works|agent)**

```
P(agent)         = 2/6 = 0.333
P(works|agent)   = count(agent,works) / count(agent) = 1/2 = 0.500

P("agent works") = 0.333 × 0.500 = 0.167
```

结论：`P("agent works") ≈ 0.167`

与 `P("datawhale agent learns")` 结果相同，因为两个句子在此语料库中统计结构对称——`agent` 后跟 `learns` 和跟 `works` 的概率各占一半。
